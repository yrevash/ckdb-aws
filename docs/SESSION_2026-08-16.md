## 4. The four blockers

### B1 — the Fargate task would crashloop before `/healthz` *(reproduced, not theorised)*

The Aug-2 audit fix **C3** hardened `runtime.py` to **fail closed** when the reader and writer DSNs
resolve to the same principal. `infra/` was never updated to match: `AppStack` injected only
`POSTMORTEM_DATABASE_URL` (the writer), and `runtime.py` falls back to it for *both* roles:

```python
writer_dsn = settings.writer_database_url or settings.database_url or ""
reader_dsn = settings.reader_database_url or settings.database_url or ""
```

Running the real code with AppStack's exact env produced:

```
RoleScopeViolation : AWS runtime mode refuses identical or same-principal
reader/writer database URLs (audit C3)
```

A security fix landing in one component while its deployer keeps the old contract. Note the existing
`reader_secret` is the **Managed MCP URL/token**, not a SQL DSN — it could never have filled this role.

**Fix:** `SharedStack` mints a new `CockroachSqlReaderSecret` (`postmortem_agent_reader`, per
`db/migrations/0007`); `AppStack` injects `POSTMORTEM_READER_DATABASE_URL` and
`POSTMORTEM_WRITER_DATABASE_URL` from **two distinct secrets**, each separately granted, and keeps
`POSTMORTEM_DATABASE_URL` because `config.validate()` still requires it.

### B2 — `cdk deploy` would succeed into a VPC with no route to the database

`SharedStack` built the VPC with `nat_gateways=0` and all compute in `PRIVATE_ISOLATED`. The only
exits are the AWS interface endpoints plus a CockroachDB PrivateLink endpoint that was created **only
if** `-c crdb_privatelink_service_name` happened to be passed. Omit it and the deploy is green and the
app is dark. Worse: CockroachDB Cloud PrivateLink is an **Advanced-tier** feature, so teams on
Standard/Basic could never use the only supported path.

**Fix:** a `crdb_egress_mode` context switch.
- `privatelink` (**default**, charter T8) — now **fails synth** with an actionable two-option message
  instead of deploying dark.
- `public` (**opt-in**) — provisions NAT + `PRIVATE_WITH_EGRESS` so Standard/Basic clusters are
  reachable; warns at synth; SQL egress narrowable with `-c crdb_egress_cidrs`.

`SharedStack` now exposes **one** compute-subnet selection that `AppStack` and `ConsolidationStack`
both consume, so no stack can hardcode a subnet type that does not exist in the other mode. The
relaxation is documented as accepted residual risk in the security charter, threat model, and controls
matrix — it is not a silent hole.

### B3 — a managed CockroachDB tier could not get a schema at all

`db/apply.sh` runs `set -eu` and executes `SET CLUSTER SETTING` before and after the migration chain.
Managed tiers commonly withhold `MODIFYCLUSTERSETTING`, so **one refusal aborted the entire schema
apply**.

**Fix:** cluster settings split into `090_changefeed_settings.sql` and `091_audit_settings.sql` so the
groups fail independently. Each can degrade under `POSTMORTEM_BOOTSTRAP_STRICT=0`, printing the exact
capability lost (C-SPANN recall / changefeed pipeline / audit logging) and its manual remediation.
**Strict stays the default** and both compose files pin it, so local dev still hard-fails. Verified
POSIX-clean under both `sh -n` and `dash -n`.

### B4 — the service would deploy and never go healthy

`agent_image_uri` fell back to a stock `public.ecr.aws/docker/library/python:3.12-slim`, which never
answers `GET /healthz`. **Fix:** required synth input, with an error naming `backend/Dockerfile`.

### B5 (found while fixing B2) — recall could only ever time out

In `privatelink` mode the task has **no internet route**, but `POSTMORTEM_MCP_URL` points at the public
`https://cockroachlabs.cloud/mcp`. Managed-MCP recall would have hung on every incident — a deploy that
passes health checks and then fails the demo. **Fix:** `POSTMORTEM_RECALL_BACKEND` defaults to `sql`
in privatelink mode and keeps `mcp` under public egress.

## 7. How to deploy now

```bash
# Advanced tier — secure default (charter T8, no compute egress)
cdk deploy --all -c account=<id> -c region=us-east-1 \
  -c agent_image_uri=<ecr-uri> \
  -c crdb_privatelink_service_name=com.amazonaws.vpce.<region>.vpce-svc-<id>

# Standard/Basic tier — opt-in NAT egress
cdk deploy --all -c account=<id> -c region=us-east-1 \
  -c agent_image_uri=<ecr-uri> -c crdb_egress_mode=public \
  -c crdb_egress_cidrs=<narrow-this>

# Managed CockroachDB that refuses SET CLUSTER SETTING
POSTMORTEM_BOOTSTRAP_STRICT=0 DATABASE_URL=<admin-dsn> ./db/apply.sh
```

Missing context now produces an actionable error naming the exact flag, instead of a dead deploy.

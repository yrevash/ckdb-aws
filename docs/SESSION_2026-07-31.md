## 3. What the three Phase 3 agents delivered

### Track A — Resilience & failover proof (COMPLETE, live-verified)
- **9-node simulated multi-region cluster** (`docker-compose.multiregion.yml`): 3 regions
  (`us-east-1` primary, `us-east-2`, `us-west-2`) × 3 zones, RF=5 (2+2+1), ports 26400-26408 /
  8090-8098. Isolated Compose project `postmortem-multiregion`; never touches the Phase-1/2 node.
- `db/bootstrap/010_multiregion.sql`: `PRIMARY REGION` + `ADD REGION`×3 + `SURVIVE REGION FAILURE`
  + re-asserts `REGIONAL BY TABLE IN PRIMARY REGION` on every table. Idempotent.
- **`resilience/`** Python package (`postmortem_resilience`): probes for RPO, RTO, freshness,
  cross-agent visibility, atomicity; harness + report writer + live tests.
- **Measured across 4 live runs (incl. a cold-start from zero volumes):** **RPO = 0 rows lost every
  time**; **RTO = 0.045–0.099s** (target <10s); liveness 9→6→9, region-down detected in 3–7s, full
  recovery ~4.6–7.5s; freshness (read-your-write) 7–190ms, `found_immediately=true`; cross-agent
  visibility 13–44ms cross-region; atomicity commit+abort both hold.
- Interesting finding (in code comments): client-side connection-refused failover recovers write
  availability *faster* than CockroachDB's internal gossip liveness flip; the harness polls until the
  liveness drop is observable so it's demonstrable on camera.
- Files: `docker-compose.multiregion.yml`, `db/bootstrap/010_multiregion.sql`, `resilience/**`,
  `scripts/failover_demo.sh`, `scripts/measure_resilience.sh`, `scripts/verify_phase3.sh`.
- Telemetry output: `evaluation/reports/phase3-resilience.json` (shape documented in the agent notes)
